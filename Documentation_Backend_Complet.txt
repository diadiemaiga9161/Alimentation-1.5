1. INTRODUCTION
================================================================================

Le système de gestion de boutique alimentaire est une application Spring Boot complète
conçue pour gérer tous les aspects d'une boutique de produits alimentaires :

- Gestion des produits avec suivi des stocks et dates de péremption
- Gestion des ventes (comptant et à crédit)
- Gestion des clients et fournisseurs
- Système de caisse multiple
- Gestion des inventaires et mouvements de stock
- Rapports et statistiques
- Authentification JWT avec rôles (Admin/Vendeur)
- API REST complète avec documentation Swagger

================================================================================
2. ARCHITECTURE GÉNÉRALE
================================================================================

L'application suit une architecture en couches typique Spring Boot :

- **Couche Présentation** : Contrôleurs REST (@RestController)
- **Couche Service** : Logique métier (@Service)
- **Couche Repository** : Accès aux données (Spring Data JPA)
- **Couche Modèle** : Entités JPA et DTOs
- **Couche Sécurité** : Configuration Spring Security + JWT
- **Couche Configuration** : Beans et configurations diverses

Structure des packages :
- com.ges.boutique/
  ├── BoutiqueApplication.java (Classe principale)
  ├── config/ (Configurations Spring)
  ├── securite/ (Authentification JWT)
  ├── utilisateur/ (Gestion des utilisateurs)
  ├── produit/ (Gestion produits/catégories/fournisseurs)
  ├── client/ (Gestion clients)
  ├── vente/ (Gestion ventes)
  ├── caisse/ (Gestion caisse)
  ├── inventaire/ (Gestion inventaire)
  ├── rapport/ (Rapports et statistiques)
  ├── exception/ (Gestion erreurs)
  └── HomeController.java (Routes frontend)

5. SÉCURITÉ ET AUTHENTIFICATION
================================================================================

**Authentification JWT :**
- Secret : configuré dans application.properties
- Expiration : 24h pour access token, 7 jours pour refresh token
- Algorithme : HS256

**Rôles utilisateur :**
- ADMIN : Accès complet à toutes les fonctionnalités
- VENDEUR : Accès aux ventes, produits, clients (lecture/écriture limitée)

**Endpoints protégés :**
- /api/auth/** : Public (login/register)
- /api/produits/** : ADMIN + VENDEUR
- /api/ventes/** : ADMIN + VENDEUR
- /api/admin/** : ADMIN uniquement
- /api/rapports/** : ADMIN uniquement

**CORS configuré pour :**
- http://localhost:4200 (Angular dev)
- http://localhost:8080 (Spring Boot)

================================================================================
9. CONTRÔLEURS REST
================================================================================

Tous les contrôleurs utilisent :
- @RestController pour API REST
- @RequestMapping avec préfixe /api/
- @PreAuthorize pour la sécurité
- @Operation pour documentation Swagger
- ResponseEntity pour réponses HTTP
- DTOs pour éviter l'exposition directe des entités

**Annotations communes :**
- @RequiredArgsConstructor (Lombok)
- @Tag pour regroupement Swagger
- Gestion centralisée des erreurs via GlobalExceptionHandler

================================================================================
10. GESTION DES EXCEPTIONS
================================================================================

**Exceptions personnalisées :**
- RessourceIntrouvableException : Ressource non trouvée (404)
- StockInsuffisantException : Stock insuffisant pour vente
- SoldeInsuffisantException : Solde caisse insuffisant
- ValidationException : Erreurs de validation

**GlobalExceptionHandler :**
- Capture toutes les exceptions
- Retourne réponses JSON standardisées
- Logging des erreurs
- Gestion spécifique par type d'exception
